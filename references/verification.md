# 验证去重与历史证据

用于开发、Review、保存推送、PR 和发布之间明确验证边界、减少重复验证，同时保持完成声明所需的新鲜证据。

## 核心规则

- 同一轮响应内，验证绑定最后一次影响代码行为的修改；后续 Review、save-only 提交 / 推送、创建 PR 或发布不重复运行同一验证
- 跨消息记录只能作为历史事实和验证范围选择依据，不能替代当前消息要求的新鲜验证
- 验证失效后只重跑受影响的最小相关范围；多仓任务中未变化的仓库不陪跑
- 用户只要求保存、提交或推送代码到远程时，按 save-only 处理，不主动触发新鲜验证
- 这是 AI 内部执行规则，不新增用户命令、验证状态文件或手工维护步骤

## 自动模式真实流程测试

本节适用于已授权的自动开发闭环；用户单独要求只读、review 或 save-only 时不扩大动作范围。

- 方案阶段按需求触发路径确定适用的自动测试：页面交互用真实页面操作和刷新断言；后端接口用真实请求验证响应与业务结果；涉及持久化、金额或状态变更时，按明确库表和本次测试单据 ID 回读数据。纯规则文档或不涉及 UI/数据库的改动可注明对应项“不适用”及理由；不能因为本轮只改后端就跳过需求原本的页面复现路径。
- 页面测试前按 [runtime.md](runtime.md) 的启动与就绪规则，在指定工作目录执行仓库已有的前端启动动作和后端 Docker 启动动作；不能只启动任务 app。核对共享服务归属、挂载及健康状态，确认前端可达、代理指向当前任务后端、后端依赖就绪后再进入浏览器。启动明细写运行附件，progress 记录结果摘要；不把后端端口当成前端入口。纯接口/数据库验证启动实际依赖，独立单测不强制启动全套服务。
- 真实页面同一阻塞默认最多尝试 2 次（首次加一次有明确依据的修正后重试）；用户指定“只重试一次”或“停止”时以该更窄限制为准。达到限制就记录已执行步骤、错误及解除条件，停止重复导航/重启/换工具；等待用户继续，不以新会话或重置浏览器清零次数。
- 优先在本任务本地 runtime 测试。先核对前端代理、后端容器挂载/端口、数据库实际连接与被测代码版本；本地网页连到远程服务器不算本任务代码验证。需要前端验证时准备隔离的任务前端或既有受控入口，不修改其他任务的代理、共享服务路由或运行资源。测试服未包含本任务版本时不得拿测试服结果冒充当前修复通过，也不为测试擅自部署。
- 本假期本地页面测试已由用户指定使用 Codex 内置浏览器（IAB）及其 browser skill，复用用户已有登录态；不得静默替换为独立 Playwright、无痕/新配置浏览器或 Chrome。后续用户明确指定其他浏览器时遵从新的指定。
- 登录检查先读取 IAB 已有受控标签页及 `user.openTabs()`；存在相关页面时用 `user.claimTab` 接管该已有页面，并从可见 DOM 核对登录状态、店铺及当前入口，不先开重复页面或退出登录。没有现成标签页时，在同一 IAB 中打开已核实的任务本地前端入口；空标签列表不代表没有持久登录态。需要后续接续时按 browser skill 保留/交接标签页，不能因资源停止而清理用户登录态。
- 复用前核对前端域名、协议、端口、应用路径及其代理指向当前任务后端。不能把其他域名、其他任务或测试服已登录当作本任务已登录，也不能为复用登录而改到错误后端。复用登录指浏览器自然携带已有会话，不读取、导出或复制 cookie、localStorage、token 或会话存储，不伪造登录态或绕过鉴权。
- `TEST_COOKIE` 未配置、独立 curl 返回401、新建页面显示登录页，都不能单独证明 IAB 没有可用登录。只有完成已有页面与任务入口核对，实际浏览器仍显示未登录或会话失效时，才记录登录阻塞，并在正确 IAB 页面提出最小登录/验证码协助；progress 记录浏览器类型、入口URL、是否接管已有标签、页面可见结果和未覆盖项，不记录凭证。有限重试次数跨会话保留，检查已有标签不会重置此前失败计数。
- 数据库只限已核实的本地库或测试服库，生产库禁止访问。正常测试数据准备/清理由本任务隔离测试库或已获授权的专用测试数据承担；不得把共享本地业务数据当作可随意清空的测试库。测试服默认只读，页面或 API 的写入同样属于测试服写操作，不能绕过单独写授权要求。结构补齐和其他数据操作仍遵守 auto-mode 的数据库边界。
- 自动执行原始复现步骤及与改动相关的关键回归，检查页面结果、真实响应/后端日志、数据库前后状态与唯一性等业务断言。数据库回读使用明确库名限定表名和窄条件。不能用 HTTP 200、没有报错、截图、mock 返回或读取旧数据中的任一项单独替代完整业务断言。
- 在 progress 记录版本、环境、测试步骤或脚本、测试数据标识、预期与实际结果、必要截图/响应摘要/数据库断言；保存的证据不得含凭证和敏感数据。已有真实自动测试通过且本轮证据仍有效时可复用，不为仪式重复运行。
- 没有尝试前不得笼统写“留待人工验收”。遇到启动/依赖/本地缺失结构问题，先在既有授权内诊断修复并重试；页面登录、测试数据、环境、部署版本或写权限确实不可用时，记录已经尝试的动作、具体错误、未覆盖项和解除条件，推送 blocked 并暂停该项交付，继续不依赖它的工作。整体不能再推进时同步暂停状态与 resume_status，不因仍是 auto 擅自恢复。
- 必需项全部通过才报告自动验证完成；“已推送”“单测通过”“测试中”均不等于真实流程自动测试已完成。保留给用户的最终业务验收只用于产品判断及用户明确要求的人工作业。

## 当前任务 Docker 日志排障

- 查看当前任务 Docker 容器日志属于只读取证，manual 和 auto 都允许；用户要求排查报错、或当前开发自测需要诊断时直接读取，不要求开启自动模式或再次授权。读取日志本身不授权改代码、改数据库或重启服务，后续动作按当前任务授权执行。
- 先由任务 `meta.yaml` 定位绑定后端，核对 compose 配置、app 容器与仓库挂载路径，确保读取当前任务实例；不要混用共享主仓或其他任务的后端日志。
- 对使用以下 compose 布局的 producer-backend，在后端仓库根目录读取近期 app 日志；其他项目先核实自己的配置，不套用不存在的文件：

```bash
docker compose --env-file docker/.env --env-file docker/.task.env \
  -f docker/docker-compose.yml -f docker/docker-compose.task.yml \
  logs --since 10m --tail 200 app
```

- 围绕失败请求的时间、路由和堆栈收敛根因，按需扩大有限时间窗口；不输出整份环境变量、连接口令或令牌，日志中的敏感信息应遮蔽。
- 缺表 / 缺字段 / 缺索引的报错应回到当前模型和数据库 schema 核对，按 `local-db-repair` 的流程处理；auto 的本地最小补齐预授权见 [auto-mode.md](auto-mode.md)，manual 沿用已有明确授权，没有授权时先给修复建议。修复代码或环境后重跑触发问题的最小验证，不以“日志暂时没报错”认定问题已解决。

## 与通用完成验证规则的关系

本文件不重新解释或覆盖 `verification-before-completion`。凡当前成功 / 完成声明、Review、创建 PR、发布或用户明确要求校验时，完整执行能证明该主张的最小充分命令，并读取完整输出和退出状态。

以下证据复用规则补充两类去重约束：同一轮响应内已经完成最终验证且之后没有失效操作时，不为后续步骤重复运行；跨消息记录用于说明某个 SHA 曾经通过什么验证和帮助选择本轮最小范围，不能替代当前消息要求的新鲜验证。

## Save-only 边界

用户要求继续自动开发时，内循环的自测、审查修复及 hook 修复按 [auto-mode.md](auto-mode.md) 连续推进，并遵守本文证据失效规则；这不改变用户单独要求 save-only 时的边界。

当用户只说“提交到远程”“推送一下”“保存代码”“代码先提交”时，目标是保存当前任务分支代码，不是证明代码已经正确。

save-only 可以做：
- 恢复任务上下文，确认目标仓库、记录分支和本次文件范围
- `git status`、`git diff`、`git add`、`git commit`、`git push`
- 推送后用 `git status --short --branch`、upstream ahead / behind 或远程 SHA 复核结果
- 如实说明本轮没有重新运行测试、类型检查或发布

save-only 不应做：
- 主动运行 test、typecheck、lint、build 或真实页面验收
- 主动执行 `prepare_task_runtime.py`
- 主动安装依赖、修复 `node_modules` 或处理前端 native binding 缺失
- 主动更新任务状态为 `测试中` / `已完成`
- 把历史验证记录表述成本轮新执行结果

如果 commit hook 失败，只展示 hook 输出和失败仓库；如果 hook 修改了文件，停止并说明新增改动。即使 hook 报的是 `@rolldown/*`、`@typescript/*` 等本地原生依赖问题，也先归类为提交环境阻断，不自动进入完整 runtime repair。默认不使用 `--no-verify`，除非用户明确授权。

## 证据类型

- **代码本地型验证**：单测、类型检查、lint、构建等，绑定实际被测代码、测试、依赖和配置快照
- **远程基线型检查**：diff、冲突风险、与默认分支的兼容性等，同时绑定本地快照和比较时的远程基线 revision
- **环境 / 数据型验收**：真实页面、接口、已部署服务、测试服数据库和可变测试数据等，同时绑定代码版本与验收时的环境状态

先判断主张属于哪一类，再决定现有证据能否复用。不同类型互不替代：本地测试通过不代表真实环境已验收，真实页面可用也不替代代码测试。

## 同一轮响应内可以复用

同一轮响应内，同时满足以下条件即可复用：

- 已知实际执行的命令、覆盖范围和成功结果
- 从该次验证到当前，没有发生会使它失效的操作
- 验证实际依赖的环境仍可用，且没有证据表明相关依赖、服务、数据库结构或关键测试数据发生变化

提交、推送、创建或更新 PR、任务文档更新，以及只读的 `status`、`diff` 和 Review，本身不会改变被验证代码，因此不使代码本地型验证失效。普通 `git add` 也不使验证失效，但不能据此假定部分暂存的 commit 与此前被测工作区等价。

工作区验证后再提交时，只有同时满足以下条件，才能把代码本地型结果复用于 commit / push / PR：验证范围内最终 commit tree 与被测内容完全等价；相关工作区已干净；commit hook 没有修改工作树、index 或最终 tree。部分暂存、commit 后仍有相关未提交改动，或无法证明 tree 等价时，相关验证失效。

## 跨消息历史证据

`progress.md` 记录了验证仓库、实际命令、范围、结果和干净 `HEAD` SHA，且当前工作区干净、当前 `HEAD` 与该 SHA 完全一致时，可以准确陈述“该 SHA 曾在记录环境通过”。该记录可用于只读分析、识别已覆盖范围和选择本轮最小充分验证，但不得表述为本轮刚刚执行或当前环境已经通过。

SHA 相同也不能证明未跟踪或忽略配置、依赖目录、runtime、真实页面、接口、测试服、数据库或关键测试数据没有变化。需要当前环境结论、当前成功 / 完成声明、Review、创建 PR、发布或用户明确要求校验时，按通用完成验证规则在当前消息执行相应验证。save-only 推送不要求把历史验证刷新为当前验证。

`fetch` 不改变本地被测代码，因此不使代码本地型验证失效。如果相关远程默认分支 revision 前移，只使依赖该 revision 的 diff、冲突风险和兼容性等远程基线型证据失效；刷新这些检查，不陪跑本地单测、类型检查或构建。

## 必须失效

发生以下任一情况后，相关验证失效：

- 修改代码、测试、依赖或配置，包括生成代码、锁文件和会影响运行行为的环境配置
- `eslint --fix`、formatter、自动修复或代码生成实际改写文件
- merge、rebase 或冲突解决，以及 checkout、cherry-pick 等使被验证内容发生变化的操作
- pre-commit 等 hook 修改工作树、index 或最终 commit tree；hook 只检查而未改内容时不失效
- 验证依赖的 runtime、数据库结构或关键测试数据发生变化
- 发布命令或其他工具产生新的受跟踪文件改动

失效只作用于受影响范围。例如只修改前端，不重跑未变化的后端测试；只修改一个后端模块，先重跑对应定向测试，不默认扩大为全仓测试。

## 执行顺序

1. 先完成会改文件的 formatter、lint fix、代码生成和冲突解决
2. 再执行最快且与改动直接相关的检查
3. 根据改动风险和项目规则决定是否需要扩大验证范围
4. 同一轮响应内的 Review、PR 和发布继续复用这次最终验证，直到对应证据出现失效操作；save-only 提交 / 推送可以说明未重跑验证，不要求补跑
5. 同一轮响应内发布前的代码本地型验证可继续复用；发布后另做必要的真实页面、接口或数据验收，不用重复本地测试代替环境验收

若用户明确要求重新执行测试，或上线闸门明确要求新鲜结果，按用户要求或项目规则执行，不做复用。

## 记录与汇报

真实流程测试按上节记录执行证据；以下仅约束额外的历史证据元数据。

- 同一轮响应内复用不要求向 `progress.md` 增加额外元数据
- 只有确需跨消息保留历史证据时，才在 `progress.md` 的“自测记录”中紧凑记录：仓库、干净 `HEAD` SHA、命令、范围、结果
- 汇报时区分“本轮新执行”和“历史记录”；新执行读取完整输出和退出状态，历史记录说明对应 SHA 和记录环境，不能把未执行的命令写成本轮刚刚执行
- 环境阻断只影响未完成的验证；已经通过且未失效的其它验证仍可保留
