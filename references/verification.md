# 验证去重与历史证据

用于开发、Review、提交、推送、PR 和发布之间减少重复验证，同时保持完成声明所需的新鲜证据。

## 核心规则

- 同一轮响应内，验证绑定最后一次影响代码行为的修改；后续只读 Review、提交、推送、创建 PR 或发布不重复运行同一验证
- 跨消息记录只能作为历史事实和验证范围选择依据，不能替代当前消息要求的新鲜验证
- 验证失效后只重跑受影响的最小相关范围；多仓任务中未变化的仓库不陪跑
- 这是 AI 内部执行规则，不新增用户命令、验证状态文件或手工维护步骤

## 与通用完成验证规则的关系

本文件不重新解释或覆盖 `verification-before-completion`。凡当前成功 / 完成声明、提交或创建 PR 要求在当前消息运行验证时，完整执行能证明该主张的最小充分命令，并读取完整输出和退出状态。

本文件只补充两类去重规则：同一轮响应内已经完成最终验证且之后没有失效操作时，不为后续步骤重复运行；跨消息记录用于说明某个 SHA 曾经通过什么验证和帮助选择本轮最小范围，不能替代当前消息要求的新鲜验证。

## 证据类型

- **代码本地型验证**：单测、类型检查、lint、构建等，绑定实际被测代码、测试、依赖和配置快照
- **远程基线型检查**：diff、冲突风险、与默认分支的兼容性等，同时绑定本地快照和比较时的远程基线 revision
- **环境 / 数据型验收**：真实页面、接口、已部署服务、测试服数据库和可变测试数据等，同时绑定代码版本与验收时的环境状态

先判断主张属于哪一类，再决定现有证据能否复用。不同类型互不替代：本地测试通过不代表真实环境已验收，真实页面可用也不替代代码测试。

## 同一轮响应内可以复用

同一轮响应内，同时满足以下条件即可复用：

- 已知实际执行的命令、覆盖范围和成功结果
- 从该次验证到当前，没有发生会使它失效的操作
- 验证实际依赖的环境仍可用，且没有证据表明相关依赖、服务、数据库结构或关键测试数据发生变化

提交、推送、创建或更新 PR、任务文档更新，以及只读的 `status`、`diff` 和 Review，本身不会改变被验证代码，因此不使代码本地型验证失效。普通 `git add` 也不使验证失效，但不能据此假定部分暂存的 commit 与此前被测工作区等价。

工作区验证后再提交时，只有同时满足以下条件，才能把代码本地型结果复用于 commit / push / PR：验证范围内最终 commit tree 与被测内容完全等价；相关工作区已干净；commit hook 没有修改工作树、index 或最终 tree。部分暂存、commit 后仍有相关未提交改动，或无法证明 tree 等价时，相关验证失效。

## 跨消息历史证据

`progress.md` 记录了验证仓库、实际命令、范围、结果和干净 `HEAD` SHA，且当前工作区干净、当前 `HEAD` 与该 SHA 完全一致时，可以准确陈述“该 SHA 曾在记录环境通过”。该记录可用于只读分析、识别已覆盖范围和选择本轮最小充分验证，但不得表述为本轮刚刚执行或当前环境已经通过。

SHA 相同也不能证明未跟踪或忽略配置、依赖目录、runtime、真实页面、接口、测试服、数据库或关键测试数据没有变化。需要当前环境结论、当前成功 / 完成声明、提交或创建 PR 时，按通用完成验证规则在当前消息执行相应验证。

`fetch` 不改变本地被测代码，因此不使代码本地型验证失效。如果相关远程默认分支 revision 前移，只使依赖该 revision 的 diff、冲突风险和兼容性等远程基线型证据失效；刷新这些检查，不陪跑本地单测、类型检查或构建。

## 必须失效

发生以下任一情况后，相关验证失效：

- 修改代码、测试、依赖或配置，包括生成代码、锁文件和会影响运行行为的环境配置
- `eslint --fix`、formatter、自动修复或代码生成实际改写文件
- merge、rebase 或冲突解决，以及 checkout、cherry-pick 等使被验证内容发生变化的操作
- pre-commit 等 hook 修改工作树、index 或最终 commit tree；hook 只检查而未改内容时不失效
- 验证依赖的 runtime、数据库结构或关键测试数据发生变化
- 发布命令或其他工具产生新的受跟踪文件改动

失效只作用于受影响范围。例如只修改前端，不重跑未变化的后端测试；只修改一个后端模块，先重跑对应定向测试，不默认扩大为全仓测试。

## 执行顺序

1. 先完成会改文件的 formatter、lint fix、代码生成和冲突解决
2. 再执行最快且与改动直接相关的检查
3. 根据改动风险和项目规则决定是否需要扩大验证范围
4. 同一轮响应内的 Review、提交、推送、PR 和发布继续复用这次最终验证，直到对应证据出现失效操作
5. 同一轮响应内发布前的代码本地型验证可继续复用；发布后另做必要的真实页面、接口或数据验收，不用重复本地测试代替环境验收

若用户明确要求重新执行测试，或上线闸门明确要求新鲜结果，按用户要求或项目规则执行，不做复用。

## 记录与汇报

- 同一轮响应内复用不要求向 `progress.md` 增加额外元数据
- 只有确需跨消息保留历史证据时，才在 `progress.md` 的“自测记录”中紧凑记录：仓库、干净 `HEAD` SHA、命令、范围、结果
- 汇报时区分“本轮新执行”和“历史记录”；新执行读取完整输出和退出状态，历史记录说明对应 SHA 和记录环境，不能把未执行的命令写成本轮刚刚执行
- 环境阻断只影响未完成的验证；已经通过且未失效的其它验证仍可保留
